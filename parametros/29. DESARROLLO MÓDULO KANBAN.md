# **1. OBJETIVO DEL BOTÓN** 

El botón KANBAN BACKLOG es el espacio donde aterrizan las acciones pendientes del usuario antes de ser organizadas, planificadas, delegadas o eliminadas. 

No es una agenda diaria.No es una agenda semanal. No es un calendario mensual. No es un tablero kanban tradicional de columnas. Es una bandeja estratégica de acciones donde el usuario vacía mentalmente tareas, pendientes, ideas, responsabilidades y compromisos de distinta índole para luego clasificarlos usando la lógica aprendida previamente en el botón MATRIZ. El propósito central es ayudar al usuario a transformar una lluvia de tareas desordenadas en decisiones accionables. 

# **2. RELACIÓN CON EL FLUJO GENERAL DE FOCUSIA** 

El flujo aprobado de Focusia es: ANUAL → MENSUAL → MATRIZ → KANBAN BACKLOG → SEMANAL → DIARIA TIME BLOCKING 

- El botón MATRIZ enseña la lógica de priorización basada en la Matriz de Eisenhower. 

- El botón KANBAN BACKLOG permite aplicar esa lógica sobre acciones reales del usuario. 

Por tanto, el usuario primero aprende a distinguir entre: Hacer – Planificar – Delegar - Eliminar Y luego aplica esa clasificación dentro del Kanban Backlog. 

# **3. FUNCIÓN PRINCIPAL DEL KANBAN BACKLOG** 

El Kanban Backlog funciona como un lugar de aterrizaje de acciones. Las acciones pueden ingresar al Kanban desde dos vías principales: 

- **A. Ingreso manual del usuario:** El usuario escribe directamente acciones, tareas o pendientes. Ejemplos: 

   - Pagar cuentas. 

   - Responder correos. 

   - Hacer compras. 

   - Llamar a alguien. 

   - Resolver temas de trabajo. 

   - Preparar una reunión. 

   - Organizar un paseo. 

   - Revisar documentos. 

   - Hacer trámites personales. 

   - Comprar medicamentos. 

   - Enviar información. 

   - Ordenar asuntos familiares. 

# **B. Acciones provenientes de otros módulos** 

Especialmente desde la Rueda de la Vida, cuando Focusia propone acciones sugeridas en las áreas foco y el usuario decide enviarlas al Kanban Backlog. La lógica aprobada desde Rueda de la Vida es: Rueda de la Vida → Áreas foco → Acciones sugeridas por IA → Enviar al Kanban Backlog Estas acciones no van directamente a la agenda, ni al semanal, ni al diario. Primero aterrizan en el Kanban para ser clasificadas.

# **4. CUÁNDO SE USA EL KANBAN BACKLOG** 

El Kanban Backlog se usa cuando el usuario tiene un cúmulo de tareas de distinta índole, distintos criterios o distintas áreas, y no sabe cómo ordenarlas. 

**Ejemplo de uso:** El usuario tiene pendientes laborales, familiares, personales, financieros, llamadas, compras, correos y trámites mezclados. En ese caso, entra al Kanban, escribe una lluvia de ideas de acciones y luego decide qué hacer con cada una. 

# **5. CUÁNDO NO ES NECESARIO USAR EL KANBAN** 

Si el usuario ya tiene claridad sobre una acción, día y hora, puede programarla directamente en la agenda semanal o diaria. Ejemplo: “Ejercitar todos los días a las 7:00 AM antes de la ducha.” 

Esa acción no necesita pasar por Kanban si el usuario ya sabe exactamente cuándo hacerla. 

# **_Nota funcional futura:_** 

_En la agenda semanal deberá existir más adelante un botón que permita repetir o copiar una misma acción todos los días a la misma hora. Ejemplo: “Repetir esta acción todos los días.” “Copiar a toda la semana.” “Repetir de lunes a viernes.”Esta funcionalidad pertenece al módulo SEMANAL / DIARIA, no al Kanban Backlog._ 

# **6. ESTRUCTURA VISUAL DEL KANBAN BACKLOG** 

El Kanban debe mostrarse como una lista de acciones. Cada acción debe tener al lado cuatro botones circulares con letras. Cada letra representa una decisión: 

H = Hacer 

P = Planificar 

D = Delegar 

E = Eliminar 

Estas letras deben estar visibles junto a cada acción para que el usuario clasifique rápidamente. 

# **7. COMPORTAMIENTO DE CADA LETRA** 

# **<u>7.1. H = HACER</u>** <u>:</u> 

Cuando el usuario presiona H, la acción se envía a la agenda diaria. **Regla clave:** La agenda diaria siempre está abierta o disponible dentro del flujo visual de Focusia. **Comportamiento funcional:** 

1. El usuario presiona H en una acción del Kanban. 

2. La acción se mueve automáticamente hacia la agenda diaria. 

3. La acción queda flotando sobre el primer espacio disponible. 

4. La ubicación sugerida se calcula desde arriba hacia abajo. 

5. Si el usuario pincha dos veces la acción, esta queda fija en ese espacio. 

6. Si el usuario no la confirma, puede arrastrarla manualmente hacia el cajón, bloque u horario que más le acomode. 

Esto permite rapidez, pero mantiene el control del usuario. 

**Regla de experiencia:** Focusia sugiere una ubicación, pero el usuario decide si la acepta o la mueve. Texto sugerido de confirmación breve: 

“Acción enviada a tu agenda diaria. Puedes fijarla aquí con doble clic o moverla al horario que prefieras.” 

# **<u>7.2. P = PLANIFICAR</u>** 

Cuando el usuario presiona P, el sistema debe preguntar dónde desea planificar esa acción. Debe aparecer una ventana o modal con tres opciones:

- A. Agenda semanal 

B. Agenda mensual 

C. Agenda anual 

Después de elegir una opción, el usuario debe poder pinchar el día o fecha donde se ubicará esa acción. 

# **Flujo funcional:** 

1. Usuario presiona P en una acción. 

2. Aparece pregunta: 

“¿Dónde quieres planificar esta acción?” 

3. Se muestran tres botones: 

   - Agenda semanal 

   - Agenda mensual 

   - Agenda anual 

4. El usuario elige una agenda. 

5. Se abre la vista correspondiente. 

6. El usuario selecciona el día o fecha. 

7. La acción queda ubicada en la agenda seleccionada. 

8. La acción sale del Kanban activo. 

9. La acción queda guardada en historial con estado “Planificada”. 

**Regla aprobada:** La acción no debe quedar duplicada en el Kanban activo. Debe salir del Kanban para evitar saturación, pero debe quedar trazabilidad histórica. 

# **Texto sugerido de confirmación:** 

“Acción planificada correctamente. Ya fue enviada a la agenda seleccionada y quedó registrada en tu historial.” 

# **<u>7.3. D = DELEGAR</u>** 

Cuando el usuario presiona D, la acción se mueve al bloque o módulo “Acciones por Delegar”. Este bloque puede estar visible debajo del Kanban o conectado con el botón independiente “Acciones por Delegar”. 

**Flujo funcional:** 

1. Usuario presiona D en una acción. 

2. La acción se mueve hacia el área “Acciones por Delegar”. 

3. Sale del Kanban activo. 

4. Queda registrada con estado “Delegada” o “Por delegar”. 

5. Más adelante podrá completarse con responsable, fecha, observación o seguimiento. 

# **Texto sugerido de confirmación:** 

“Acción enviada a Acciones por Delegar.” 

Nota: 

El detalle de seguimiento de acciones delegadas será desarrollado en el botón correspondiente. En este módulo solo debe enviarse correctamente. 

# **<u>7.4. E = ELIMINAR</u>** 

Cuando el usuario presiona E, la acción se envía a un basurero de ideas desechadas. No se borra definitivamente en primera instancia. 

Debe quedar guardada en un contenedor de descarte, para permitir recuperación si el usuario se equivoca. 

# **Flujo funcional:** 

1. Usuario presiona E. 

2. La acción sale del Kanban activo.

- Planificada en agenda mensual. 

- Planificada en agenda anual.

# **10. HISTORIAL DE MOVIMIENTOS** 

El sistema debe registrar el historial de cada acción. Ejemplo: 

Acción creada manualmente → En Kanban activo → Clasificada como P → Enviada a Agenda semanal → Fecha seleccionada: jueves 25 de junio → Estado: Planificada. 

Este historial no necesariamente debe mostrarse al usuario en la vista principal, pero debe quedar guardado para futuros reportes o seguimiento. 

# **11. PRINCIPIO CENTRAL DE USABILIDAD** 

El Kanban debe ser rápido, simple y visual. El usuario no debe sentir que está llenando formularios. Debe poder: 

- Escribir acciones rápidamente. 

- Verlas en lista. 

- Clasificarlas con H/P/D/E. 

- Enviarlas al destino correcto. 

- Vaciar su mente. 

- Ordenar sus decisiones. 

# **12. RELACIÓN CON MATRIZ** 

El botón MATRIZ enseña el significado de: Hacer 

Planificar Delegar Eliminar 

El Kanban aplica esta lógica. 

Por eso no es necesario volver a explicar extensamente la Matriz dentro del Kanban. Solo se puede mostrar una ayuda breve si el usuario la necesita. 

Ejemplo de ayuda opcional: H = Hacer ahora. 

P = Planificar para otro momento. 

D = Delegar a otra persona. E = Eliminar o desechar. 

# **13. RELACIÓN CON SEMANAL** 

Las acciones clasificadas como P pueden ir a la agenda semanal si el usuario así lo decide. El módulo semanal recibirá acciones ya planificadas desde Kanban. Más adelante, en el módulo semanal, se deberá desarrollar: 

- Visualización semanal. 

- Copiar acciones repetidas. 

- Repetir acciones todos los días. 

- Organizar bloques horarios. 

- Mover acciones entre días. 

- Conexión con agenda diaria. 

# **14. RELACIÓN CON DIARIA TIME BLOCKING** 

Las acciones clasificadas como H van directamente a la agenda diaria. La acción queda flotando sobre el primer espacio disponible de abajo hacia arriba. 

El usuario puede: 

- Confirmarla con doble clic.

# **15. RELACIÓN CON ACCIONES POR DELEGAR** 

Las acciones clasificadas como D se envían al espacio “Acciones por Delegar”. Este módulo deberá permitir posteriormente: 

- Asignar responsable. 

- Definir fecha de seguimiento. 

- Agregar observación. 

- Marcar como realizada. 

- Revisar estado. 

En el Kanban solo se define el envío inicial. 

# **16. RELACIÓN CON BASURERO DE IDEAS DESECHADAS** 

Las acciones clasificadas como E se envían a un basurero. 

El objetivo es limpiar el Kanban activo sin borrar definitivamente la información. 

El usuario debe poder revisar ideas desechadas si se requiere. 

# **17. CASOS ESPECIALES** 

17.1. Acción sin clasificar 

Si una acción está escrita, pero no tiene H/P/D/E seleccionada, permanece en el Kanban activo. 17.2. Usuario se equivoca al clasificar 

Debe existir opción de deshacer inmediatamente después de mover una acción. Texto sugerido: 

“Acción movida. ¿Deshacer?” 

17.3. Acción enviada a Planificar, pero usuario cancela 

Si el usuario presiona P, pero luego cancela antes de elegir agenda o fecha, la acción debe permanecer en el Kanban activo. 

17.4. Acción enviada a Hacer, pero usuario no confirma ubicación 

La acción queda flotando en la agenda diaria hasta que el usuario la fije o la mueva. 

17.5. Acción duplicada 

El sistema puede advertir si el usuario escribe una acción muy similar a otra existente, pero no debe bloquearlo. 

Texto sugerido: 

“Parece que ya tienes una acción similar. ¿Quieres guardarla de todas formas?”

# **19. RESUMEN FUNCIONAL FINAL** 

El Kanban Backlog de Focusia es el lugar donde el usuario aterriza acciones pendientes cuando necesita ordenar su mente. 

Cada acción se clasifica con una de cuatro decisiones: 

- H = Hacer → va a agenda diaria. 

- P = Planificar → abre agenda semanal, mensual o anual para elegir fecha. 

- D = Delegar → va a Acciones por Delegar. 

- E = Eliminar → va al basurero de ideas desechadas. 

El Kanban no reemplaza la agenda. 

El Kanban no reemplaza la planificación semanal. 

El Kanban ordena el caos antes de calendarizar. 

Su función es transformar una lluvia de tareas en decisiones concretas.
